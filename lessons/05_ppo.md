# 第 5 课：真正训练一个 PPO 控制器

这一课实际训练神经网络，让它通过自己与单摆交互，尝试把关节移动到 0.5 rad 并保持。你已经懂得“读状态—算控制量—推进动力学”；现在要读懂的是：**采集一批交互数据，怎样变成下一版控制器的参数。**

## 1. 环境继续定义“做什么算好”

本课沿用第 4 课的任务：

| 项目 | 本课设置 |
| --- | --- |
| 观察 `obs` | `[0.5-q, dq]`，长度为 2 |
| 动作 `action` | 长度为 1，范围 `[-1,1]` |
| 物理输入 | 电机力矩 `u = 2 * action` N·m |
| 物理步长 | 每个 `mj_step` 推进 0.002 秒 |
| 控制步长 | 每个 `env.step` 保持动作 10 个物理步，共 0.02 秒 |
| 初态 | `q`、`dq` 各自在 ±0.05 内随机采样 |
| 回合 | 失败结束，或采样达到 400 步，即 8 个模拟秒 |
| 奖励 | `1 - 4*error² - 0.05*dq² - 0.001*u² - 10*失败指示量` |

`info` 可以保存真实状态、力矩、分项代价，便于我们检查；它不是额外送入 actor 的输入。目标固定，因此 error 已经能确定 q。改变显示窗口的按键说明，不改变这里的动力学和学习任务。

PD+重力补偿只作为外部对照：它使用已知模型的 bias。PPO 通过自己的动作和奖励学习，两者获得的信息不同，不能把两者的分数差解释成某种算法普遍优劣。

## 2. `train()`：先认出网络与真正的训练语句

在创建 `PPO(...)` 的地方，先找这几项：

```python
policy_kwargs = dict(
    net_arch=dict(pi=[64, 64], vf=[64, 64]),
    log_std_init=-0.5,
)
```

`pi` 是 actor，即控制动作的网络；`vf` 是 critic，即价值估计网络。两者都输入两个观察量，各有两层、每层 64 个神经元。actor 输出连续动作分布的均值，另有可学习的标准差参数；critic 输出一个价值数。这里的 `64` 是网络宽度，不是采样步数。[SB3 网络说明](https://stable-baselines3.readthedocs.io/en/master/guide/custom_policy.html)

可以把执行阶段的路径画成：

```text
[error, dq] → actor 网络 → 动作 → 限幅到 [-1,1] → 力矩 2*动作 → MuJoCo
      ↑                                                       │
      └──────────────── 下一次观察 ────────────────────────────┘
```

网络的权重和偏置就是可学习参数，功能上相当于一种可调整的反馈控制律。它可以学出状态相关的非线性关系，但代码没有预先规定必须学成 PD，也没有把重力补偿公式藏进网络输出。

创建 `PPO(...)` 只得到初始化后的网络。**真正更新参数的是 `model.learn(...)`**。`model.save(...)` 保存当时参数，`PPO.load(...)` 恢复参数，`model.predict(...)` 根据当前参数算动作；后三者本身都不会继续学习。

本课使用 SB3 2.9.2 和 PyTorch 2.9.1+cpu；复现实验时对照 `config.json` 的运行配置、PyTorch 版本，以及 `sources/requirements.txt` 的依赖快照。小型 MLP 使用 CPU 即可，先把整个过程读明白。

## 3. `model.learn()` 内部重复三个阶段

下面是理解顺序的伪代码，不是需要你再实现一次的训练器：

```python
while 交互步数还未达到要求:
    batch = 用当前策略与环境交互并记录数据()
    advantages, value_targets = 根据奖励和价值估计计算GAE(batch)
    for epoch in range(10):
        for minibatch in 打乱并分批(batch, size=256):
            更新actor和critic(minibatch)
```

**第一阶段：采样。** 策略实际控制 MuJoCo，记录观察、采样动作、奖励、结束信息、旧动作概率和旧价值估计。这些都是“发生过什么”的数据。训练中的动作从分布采样，使策略能探索不同动作。

**第二阶段：算优势和价值目标。** 把后续奖励与 critic 的预测合起来，估计某次动作带来的结果是否比原来预期好。这个相对评价叫 advantage，优势。它可以为正或为负；不是简单地把正 reward 当好动作、负 reward 当坏动作。

**第三阶段：更新。** 对同一批数据打乱、分成小批，多轮调整网络参数。actor 倾向提高正优势样本中动作的概率，降低负优势样本中动作的概率；critic 调整自己的未来回报预测。随后丢开这批旧数据，用更新后的策略收集下一批。[PPO 原论文](https://arxiv.org/abs/1707.06347)

梯度在 PyTorch 的网络和损失函数中计算。MuJoCo 提供采样得到的状态与奖励，**这里没有对 MuJoCo 的积分过程反向传播**，也没有用动力学导数计算“力矩加一点，未来奖励精确改变多少”。

熟悉 MPC 时可以这样对应：两者都关心连续动作带来的未来结果；本课 PPO 把大量优化工作放在训练期间，执行时直接用网络计算当前动作，没有在每个控制时刻重新求解一段输入序列。

## 4. 这些数字各数什么

| 参数 | 本课数值 | 应如何理解 |
| --- | --- | --- |
| `n_envs` | 4 | 4 个独立环境，分别有自己的状态和回合 |
| `n_steps` | 256 | 每轮更新前，每个环境各采集 256 个控制步 |
| 一轮样本量 | 1024 | `4 × 256` 条环境转移 |
| `batch_size` | 256 | 一次梯度更新使用的样本数 |
| `n_epochs` | 10 | 同一轮采样数据重复训练 10 遍 |
| 每轮梯度更新 | 40 | `1024 / 256 × 10`，按完整一轮计算 |
| `learning_rate` | `3e-4` | 优化器的步长设置 |
| `gamma` | 0.99 | 训练中未来奖励的折扣因子 |
| `gae_lambda` | 0.95 | GAE 综合不同时长估计的参数 |
| `clip_range` | 0.2 | PPO 概率比裁剪目标中的参数 |
| `seed` | 42 | 本轮训练的随机种子 |

这四个环境由 `DummyVecEnv` 管理：同一进程按顺序推进，并不是真正同时执行四个物理仿真。每个环境各走 256 步，对应各自 5.12 个模拟秒；`num_timesteps` 则累加全部环境步数。把三种尺度分开：**物理积分每 0.002 秒一次，控制决策每 0.02 秒一次，PPO 收满 1024 条转移后进行一轮更新。** 模拟时间也不同于电脑实际花费的时间。不能把训练 200000 步理解成一个连续的 4000 秒轨迹，更不能当成 200000 次网络更新。[DummyVecEnv 实现](https://stable-baselines3.readthedocs.io/en/master/_modules/stable_baselines3/common/vec_env/dummy_vec_env.html)

一轮可以跨越回合结束，也可以在某个回合中间收满 256 步。采样窗口、回合、minibatch 是三种不同的划分。PPO 通常完成整轮采样后再停止，所以实际步数可能略超过 `--steps` 指定值；以配置与日志中记录的实际步数为准。[SB3 PPO 参数](https://stable-baselines3.readthedocs.io/en/master/modules/ppo.html)

## 5. `evaluate()`：拿同一组初态比较四个控制器

脚本中 `evaluate_saved()` 负责加载各个模型，调用 `evaluate(model)` 跑完整回合；传入 `None` 时使用 PD 对照。先读单个回合的循环，再看四组怎样汇总。

训练时会探索，正式比较时使用 `model.predict(obs, deterministic=True)`。本课连续高斯策略取均值并按动作范围裁剪，评估过程中不再更新参数。未训练网络也必须用同一评估规则，才能把变化归因于训练。

四组分别是：

| 名称 | 含义 |
| --- | --- |
| initial | 调用 `learn()` 之前保存的网络 |
| best | 中途验证得分最高时保存的网络 |
| final | 本轮训练结束时的网络 |
| PD | 已知 PD+重力补偿对照 |

initial 也不等于第 4 课的均匀随机动作：一个是初始化网络的确定性输出，一个是每步独立抽取随机动作。

中途验证用 seeds 900～904，帮助选择 best；最终评估用 seeds 1000～1009，四组各跑相同的 10 个初态。最终这组不参加梯度训练，也不用于中途挑选 best。若以后根据这组结果反复调参，它就逐渐承担了验证集的作用，不能继续声称是完全未参与决策的最终测试。

打开本轮 `evaluation.json`，同时检查：

- **回报和回合长度**：回报是本局 reward 的直接累加，是否完成 400 步必须单独看。
- **失败数**：`terminated` 表示越过任务失败边界；没有失败且到 400 步属于时间截断。
- **最后 50 步的位置误差**：一秒稳定保持情况，关注最大绝对误差，不能只看最后一个点。
- **最后 50 步的速度**：使用速度 RMS 检查是否仍在振荡，误差较小不自动表示已经停稳。

对于提前失败的回合，“最后 50 步”只是失败前的窗口，不能当作完成 8 秒后的稳定性能。

可以先采用以下教学验收门槛：10/10 回合均完成 400 步，平均回报至少 350；每个完成局的末 50 步最大绝对误差不超过 0.05 rad，速度 RMS 不超过 0.1 rad/s。这些是本课预设的参考标准，**是否达到必须读取本轮结果，不能仅凭成功执行 `learn()` 或窗口看起来平稳来判断。**

best 不一定等于 final，因为学习过程允许波动。训练日志中的回报还包含探索噪声，与确定性评估回报有不同口径。单次训练、10 个小扰动初态的结果，也不能证明面对大角度初态、外力扰动或其他模型仍然有效。

### 本次实际运行结果

实验目录是 `artifacts/lesson05/run_20261102T020019_195535Z/`。请求训练 200000 步，实际完成 200704 个环境步，训练与中途验证共耗时约 48.45 秒；这是本次机器上的记录，不是以后每次训练的耗时保证。用保存后重新加载的模型，在 seeds 1000～1009 上得到：

| 控制器 | 平均回报 ± 标准差 | 最坏末窗最大误差 / rad | 最坏末窗速度 RMS / rad·s⁻¹ |
| --- | --- | --- | --- |
| initial | 58.93 ± 18.98 | 0.62659 | 1.2471 |
| best | 375.90 ± 2.14 | 0.015125 | `4.30e-6` |
| final | 375.19 ± 2.10 | 0.042457 | `8.05e-9` |
| PD+重力补偿 | 370.32 ± 2.72 | `2.56e-7` | `7.27e-7` |

四组都是 10/10 完成 400 步、失败数为零。表中的“最坏”是在 10 个回合各自的最后 50 步指标中取最大值；误差和速度的最坏值不一定来自同一回合。标准差描述这 10 个初态的回报离散程度，不是多次独立训练的波动。

本次 best 通过上述教学验收。未训练网络也能坚持 400 步，却明显没有稳定跟踪目标，说明“没有越过失败边界”只是较宽松的条件。best 与 final 的速度都已很小，但仍有可见位置偏差，说明“停稳”与“准确到达”仍需分别检查。

best 的验证最高平均回报约 376.29，出现在累计 40000 个环境步的验证记录处；继续训练到最后没有得到最高分。保存前后的确定性探针动作完全一致，最终参数相对初始参数的变化 L2 范数约 20.52。这些证据分别回答“确实更新了参数”和“文件恢复后仍是同一个控制器”。

PPO 在这组初态上的全回合回报略高于 PD，而 PD 的稳态位置精度明显更高。总奖励把过渡过程、保持阶段和力矩代价加在一起，因此两种指标的排序可以不同；这个例子不能证明 PPO 普遍优于 PD。学习出的非零偏差也不是“为了抵消重力在物理上必须保留的误差”：有偏置能力的控制律可以在零误差处输出非零力矩，当前偏差还受奖励取舍和有限训练影响。

这些结论只对应训练 seed=42、固定模型与目标、附近的小扰动初态。若要讨论训练稳定性或更大范围的鲁棒性，需要额外的训练种子与测试条件。

先读 `evaluation.json`，再看 `validation.csv`，最后结合 `batch_example.json` 读后面的公式。`progress.csv` 的 loss 不是角度误差；actor loss 变小也不能单独证明控制质量更好。

样本文件的 `reward` 字段来自 SB3 rollout buffer。这次 `batch_example.json` 保存第一批的第一个样本，尚未遇到时间上限，所以这里等于环境原始奖励。但一般情况下，某个样本若恰逢时间截断，buffer reward 可能已加入 `gamma * V(末状态)` 的 bootstrap 修正；`last_batch_example.json` 也遵循这个口径。不要始终把该字段直接代回环境奖励公式，后面的“深读 D”解释原因。

保存加载检查应对同一组观察，比较保存前和重新加载后的确定性动作。这能验证模型文件恢复了控制规律；控制性能是否足够好，仍由独立的完整回合评估来回答。

## 7. `play()`：执行时究竟还剩什么

回放的核心仍是第 4 课的循环：

```python
obs, info = env.reset(...)
while 未结束:
    action, _ = model.predict(obs, deterministic=True)
    obs, reward, terminated, truncated, info = env.step(action)
    env.render()
```

每隔 0.02 个模拟秒，actor 看新的 `[error, dq]`，重新计算动作。因此它是闭环反馈，不是把训练时某条动作时间序列播放一遍。此处没有 `learn()`，也没有优化器更新。

到达目标后仍需要非零力矩平衡重力。网络若学会保持，完全可能在误差很小时仍输出非零动作。奖励同时惩罚位置误差、速度和力矩，权重存在取舍，加上有限数据、网络容量与优化误差，PPO **不保证严格零静差**。既不能把任意静差都解释成物理上必需，也不能只看到非零力矩就认为策略有问题。

## 深读 A：critic 的“价值”与记录的回报不同

下面用状态记号 `s` 表示本课提供给网络的观察。critic 近似预测：

\[
V^\pi(s_t)=\mathbb{E}_\pi\left[\sum_{k=0}^{\infty}\gamma^k r_{t+k}\mid s_t\right].
\]

这是从当前状态出发、接下来沿当前策略行动时的**未来折扣奖励总和的期望**，不是当前一步的奖励，也不是精确的未来预言。发生真正终止后，不再继续累计奖励。

`evaluation.json` 中的 episode return 则是观察到的这个回合的 `r0+r1+...`，不打折。因此 critic 数值不必等于“还剩几步乘以平均奖励”，也不必等于表中 400 步的总分。

直观例子：若以后每一步奖励都恰好是 1，且一直继续，`gamma=0.99` 的价值是 `1/(1-0.99)=100`；实际截取 400 步的直接累计回报则是 400。这个例子用来区分定义，不是在预测本课会获得这些数值。

## 深读 B：优势怎样把后续结果归给当前动作

先忽略结束边界，一个 TD 残差可以写成：

\[
\delta_t=r_t+\gamma V_{\rm old}(s_{t+1})-V_{\rm old}(s_t).
\]

它比较“一步真实奖励，加上下一状态的预测”与“之前对当前状态的预测”。GAE 再把后续 TD 残差按距离衰减相加：

\[
\hat A_t=\delta_t+(\gamma\lambda)\delta_{t+1}
            +(\gamma\lambda)^2\delta_{t+2}+\cdots.
\]

这里 `lambda=0.95`，样本窗口边界处会使用适当的价值估计。它让当前动作的评价考虑后续结果，同时借助 critic 减少估计波动；估计本身仍可能有误差。[GAE 原论文](https://arxiv.org/abs/1506.02438)

SB3 用未标准化的 GAE 构造 critic 的目标：

\[
\hat R_t=\hat A_t+V_{\rm old}(s_t).
\]

critic 拟合这个固定目标；actor 更新时再按 SB3 的设置标准化优势。不要把 actor 使用的标准化优势直接加回旧价值，误当作 critic 目标。

用 `batch_example.json` 找一个具体样本，依次说出：输入观察是什么、采取了什么动作、随后 reward 是多少、critic 原先估计多少、优势为正还是为负。初学阶段能把这些量串起来，比背下 GAE 的完整推导更重要。

## 深读 C：PPO 的 clip 究竟裁剪什么

对采样时采取的同一个动作，计算它在新、旧策略下的概率密度比：

\[
\rho_t(\theta)=
\frac{\pi_\theta(a_t\mid s_t)}{\pi_{\rm old}(a_t\mid s_t)}
=\exp\bigl(\log\pi_\theta(a_t\mid s_t)-\log\pi_{\rm old}(a_t\mid s_t)\bigr).
\]

连续动作使用概率密度，而不是“精确取到某一个实数的概率”。旧策略的 log probability 在采样时存好，更新过程中固定；新策略的 log probability 随网络参数变化。

PPO 的 actor 目标是最大化样本平均：

\[
L^{\rm clip}(\theta)=\mathbb{E}_t\left[
\min\left(\rho_t\hat A_t,
\operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)\hat A_t\right)
\right],\qquad \epsilon=0.2.
\]

正优势样本上，继续大幅提高动作概率所能增加的目标收益会受到抑制；负优势样本上，过度降低概率也有相应限制。实现时常把这个目标加负号，交给最小化 loss 的优化器。

**裁剪的是目标函数中的概率比项，不是把所有新策略概率比强制锁在 `[0.8,1.2]`，更不等于给物理力矩再做一次 ±20% 限幅。** 实际参数更新可能使部分样本的概率比越界，策略性能也可能暂时退步。不要把 clip 理解成硬性稳定性保证。[SB3 PPO 参数与限制](https://stable-baselines3.readthedocs.io/en/master/modules/ppo.html)

还有另一种完全不同的裁剪：标准连续动作 PPO 从高斯分布采样，样本可能超出 `[-1,1]`，送给环境之前需要按动作边界裁剪。训练缓存中可能保存分布采样的原始动作，用于计算其 log probability；实际执行的是裁剪后动作，物理力矩对应后者。两种动作在未越界时相同，越界时不相同。[SB3 连续动作处理](https://stable-baselines3.readthedocs.io/en/master/_modules/stable_baselines3/common/on_policy_algorithm.html)

## 深读 D：回合截断时为什么还要预测未来

本任务要求持续保持目标，400 步是为了有限时间采样，不表示第 400 步之后的状态失去价值。因此：

- 真正失败 `terminated=True`：不从失败终态继续 bootstrap，下一步价值按零处理。
- 时间截断 `truncated=True`：仍使用最后状态的价值，估计假如继续运行还能得到什么。

如果把所有结束都当作“未来价值为零”，critic 会错误地把正常保持到 8 秒的状态当成价值突然消失。这里无需你在环境中手动补奖励：`DummyVecEnv` 保存末状态和超时标记，SB3 的采样代码完成相应处理。[Gymnasium 时间上限说明](https://gymnasium.farama.org/tutorials/gymnasium_basics/handling_time_limits/)、[SB3 采样实现](https://stable-baselines3.readthedocs.io/en/master/_modules/stable_baselines3/common/on_policy_algorithm.html)

这也说明为什么本课的观察里没有“倒计时”：我们把它建模为持续保持任务的采样截断。若未来定义“只在恰好 8 秒内完成，结束时间本身属于任务”，就要重新考虑时间观测与终止语义。
